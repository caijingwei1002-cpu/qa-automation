## 学习记录

今天理解了：URL 断言只能证明去了某个路由；商品名称断言证明打开的是目标商品；价格断言证明关键业务数据在列表页和详情页之间一致；返回后的 URL 和标题共同证明列表页重新恢复。

它解决的问题：防止测试直接访问详情 URL 或只检查 URL，导致真实点击链路、商品身份、字段错配和返回页面渲染问题被漏检。

我实际如何使用它：在 `test_product_detail.py` 中先登录并定位唯一的 `Sauce Labs Backpack`，用独立预期值验证列表名称和价格，点击列表中的商品名称，验证 `/inventory-item.html?id=...`、详情名称和价格，再点击 `Back to products` 并验证商品列表 URL 和 `Products` 标题。

遇到的问题：目标测试没有业务断言失败，执行结果为通过。检查命令输出时终端曾出现 PSReadLine `ArgumentOutOfRangeException`，另外 Git 暂存区存在目标文件的旧空版本。

根因或当前假设：PSReadLine 异常是终端输入/渲染问题，最终有效输出仍显示测试结构；空暂存版本是此前遗留的 Git 暂存状态，不是测试逻辑失败。收尾时需要显式暂存完整工作区文件。
