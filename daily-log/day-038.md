## 学习记录

今天理解了：POST 测试要验证 JSON 请求体、成功状态、资源 ID 和返回资源字段，而不是只看一个 2xx 状态码。

它解决的问题：避免服务返回成功消息但没有有效资源，或创建结果错误地使用默认值、旧数据而测试仍然通过。

我实际如何使用它：在 `test_create_booking.py` 中使用 `requests.post(..., json=payload, timeout=3.0)`，检查 `bookingid` 为整数，并逐项比较返回 `booking` 与 payload。

遇到的问题：代码审查发现 URL 配置需要复用 `RESTFUL_BOOKER_URL`，并需要补齐 `os` 导入和响应字段一致性断言。

根因或当前假设：硬编码 URL 会绕过环境切换；缺少导入会在收集阶段失败；只验证响应结构类型不足以证明创建内容正确。修正后目标测试和全量回归均通过。
