## 学习记录

今天理解了：环境恢复必须由操作对象确认和授权 Gate 控制，业务缺陷回归必须由服务身份、health 和基础 API 组成的 RoomBaselineReady 状态放行。

它解决的问题：避免 PID 变化后的误杀，避免未授权的环境变更，避免把外部服务、启动失败或健康失败误报为 Room 业务缺陷。

我实际如何使用它：保留操作前快照，重新核对 PID 与端口，默认让 `stop_authorized=false`，没有授权就只读调查并记录 `BLOCKED_BY_AUTHORIZATION`。

遇到的问题：外部 Node 项目仍占用默认 `3001`，本轮没有获得停止或迁移授权。

根因或当前结论：前置身份已确认，但环境变更授权未成立；Platform Room 未启动，不能进入 DELETE→GET `500` 回归，也不能形成新的产品缺陷结论。
