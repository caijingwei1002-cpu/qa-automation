## 学习记录

今天理解了：稳定定位不是简单地把所有 CSS 改成 role，而是根据用户可感知语义、业务对象和结构范围组合定位器。role、label、placeholder 和唯一文本适合表达用户看到或操作的元素；CSS 可以用于锁定稳定的结构容器；状态 class 只适合做状态断言，不应成为主要目标定位器。

它解决的问题：降低测试对前端 CSS class、DOM 层级和实现细节的耦合，减少无业务变化的前端重构导致的测试误报和维护成本。

我实际如何使用它：新增 `test_locators.py`，使用 `.todo-list` 容器内的 `get_by_role("listitem")` 找 Todo 业务对象，再在目标 Todo 内使用 `get_by_role("checkbox")` 或作用域内的 `get_by_role("button")`。筛选链接继续使用带名称的 `get_by_role("link")`；重复文本通过业务对象作用域缩小范围。

遇到的问题：

1. 直接运行 `pytest` 命令不可用。
2. 虚拟环境在沙箱中无法启动 Playwright 子进程。
3. 初次授权运行暴露全页 `listitem` 定位过宽。

根因或处理：

1. PATH 未配置 pytest，改用项目虚拟环境 Python。
2. 沙箱禁止 Windows named pipe，授权环境重跑测试。
3. 页面筛选导航也包含 `li`，为所有 Todo listitem 增加 `.todo-list` 结构作用域。
