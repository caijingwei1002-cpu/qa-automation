## 学习记录

今天理解了：Page Object 是页面操作接口，集中封装 locator、输入和点击等 UI 细节；测试文件保留测试场景、数据和业务结果断言。

它解决的问题：当登录控件的选择器或操作细节变化时，只需调整 `LoginPage`；测试仍然像“用什么数据登录 → 应该看到什么结果”的业务说明。

我实际如何使用它：在 `login_page.py` 中集中定义用户名、密码、登录按钮和错误提示 locator，并提供 `login(username, password)`；在 `test_login.py` 中通过页面对象执行三个场景，继续在测试中断言商品页 URL、标题、错误文案和未导航状态。

遇到的问题：初版把 `login_page = LoginPage(saucedemo_page)` 写入函数参数列表，导致语法错误；仓库根目录运行时找不到 `pages`；受限环境首次启动 Playwright 子进程时出现 `WinError 5`。

根因与解决方案：函数参数只能声明 fixture，页面对象初始化必须在函数体内；`pages` 导入问题源于项目目录未进入模块搜索路径，验证时从项目目录运行并用临时 `PYTHONPATH` 复现计划路径；`WinError 5` 是当前执行环境的进程/命名管道权限限制，授权环境复验通过。
