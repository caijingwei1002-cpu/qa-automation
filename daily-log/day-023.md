## 学习记录

今天理解了：移除测试要围绕状态转换设计，从“未加入”经过 Add to cart 进入“已加入”，再经过 Remove 回到“未加入”。点击没有异常只是操作层证据，按钮恢复、徽标归零和购物车条目消失才是业务结果证据。

它解决的问题：防止列表页局部状态、全局购物车计数和购物车实际内容不同步。幂等思路要求重复表达同一移除意图时最终状态稳定，但 SauceDemo UI 第一次移除后会把 Remove 变为 Add to cart，因此本日不把连续点击同一个 Remove 按钮作为有效的 UI 幂等测试。

我实际如何使用它：在第一条测试中从商品列表加入并移除 Backpack，验证商品卡片按钮、徽标和购物车为空；在第二条测试中进入购物车移除 Backpack，验证购物车条目与徽标归零，再返回列表确认 Backpack 恢复为 `Add to cart`。每条测试使用独立 fixture 状态，避免购物车历史数据污染结果。

遇到的问题：测试逻辑没有失败，也没有运行环境阻塞。收尾检查时目标文件显示为已暂存且工作区仍有同文件修改，最终会统一重新暂存目标文件，不影响测试内容。

根因或当前假设：Git 状态来自保存过程中同一目标文件同时存在 index 和工作区差异；这是版本控制状态问题，不是测试逻辑问题。未修改无关的 TodoMVC 截图目录。
