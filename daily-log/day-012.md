## 遇到的问题和解决方案

1. 重构过程中曾将边界测试数据误改为固定文本或错误空格。根因是替换动作时没有保持原始测试数据语义；逐项对照原测试后恢复了前后各两个空格、重复文本和 `long_text` 参数。
2. fixture 抽取动作后留下了未使用的 `todo_input` 变量和多余空行。根因是删除重复代码后没有同步清理；已删除并重新检查 diff。
3. Git 提示部分文件会发生 LF/CRLF 转换。根因是 Windows `core.autocrlf=true`；`git diff --check` 无 whitespace error，测试执行不受影响。
4. 最终测试没有失败，因此没有新的失败截图或 Trace；本日成功运行结果已保存为 Markdown 验证证据。

## 知识验收

1. `add_todo` 回答“怎么做”，可以被多个测试复用；`expect` 回答“本测试要证明什么”，应留在测试函数中。
2. `13 passed` 证明当前环境下收集并执行的 13 条已有测试全部通过，不等于产品没有未覆盖缺陷，也不等于所有浏览器和操作系统都已验证。
3. 抽取动作不应抽走数据控制逻辑：循环仍决定创建多少条 Todo，参数化仍决定使用哪组文本。
