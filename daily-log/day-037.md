## 学习记录

今天理解了：`200` 只证明 HTTP 层成功，集合接口还必须验证合法 JSON、顶层列表、元素对象类型和必需字段。

它解决的问题：避免只看到成功状态码就产生假通过，并让失败定位到顶层结构、元素索引或缺失字段。

我实际如何使用它：在 `test_get_bookings.py` 中通过 `RESTFUL_BOOKER_URL` 构造 `/booking`，设置请求超时，遍历列表并用索引、实际类型和实际对象构造可解释失败信息。

遇到的问题：代码审批时发现首次版本使用硬编码 URL，且引用了未定义的 `REQUEST_TIMEOUT_SECONDS`。

根因或当前假设：硬编码 URL 会绕过环境配置；未定义超时常量会在测试执行阶段触发 `NameError`。补充环境 URL 解析和 `3.0s` 常量后，目标测试及 API 全量通过。
