## 实验前问答

问题 1：两个测试同时使用相同 firstname 会有什么风险？
回答：过滤结果可能包含两个测试的数据，断言会随机失败；详情遍历可能读到别人的资源；按查询结果清理还可能删除另一个测试的 booking。

问题 2：唯一测试数据和资源所有权分别解决什么问题？
回答：唯一字段帮助查询识别本测试的数据，创建后登记的 booking ID 决定谁有权清理资源。唯一字段不能替代所有权记录。

问题 3：串行通过而并行失败时优先检查什么？
回答：优先检查共享数据、查询条件、全局状态、fixture、端口、缓存、执行顺序和 teardown 竞态，不先用 retry 掩盖隔离问题。

问题 4：如何判断串行和并行结果真正一致？
回答：不仅比较 passed 数量，还要核对每个实例能找到并更新自己的资源，详情属于自己的唯一数据，并且每个 fixture 只清理自己登记过的 ID。

## 学习记录

今天理解了：并行隔离不是让请求强行同时发生，而是让每个测试在任意调度顺序下都只依赖自己的数据和资源。唯一业务字段负责识别，创建后登记的 ID 负责所有权，fixture finally 负责可靠清理。

它解决的问题：共享姓名、宽查询和批量 teardown 会让串行隐藏的测试耦合在并行执行时暴露。按唯一字段过滤并回查详情，可以证明查询没有混入别人的资源；按登记 ID 清理，可以防止跨测试删除。

我实际如何使用它：在参数化测试中复用 `created_booking`，读取自己的 `booking_id` 和唯一 firstname；过滤场景断言自己的 ID 和详情字段；更新场景只 PUT 自己的 ID，并 GET 验证持久化；串行和 `-n 2` 都运行同一文件。

遇到的问题：第一次执行并行命令时 pytest 报 `unrecognized arguments: -n 2`，测试尚未收集。

根因与修复：当前虚拟环境没有加载 pytest-xdist，且目标项目依赖未声明。将 `pytest-xdist>=3,<4` 加入 `test-projects/03-restful-booker-api/requirements.txt` 并安装后，并行测试正常执行。这个失败属于运行环境能力缺失，不是隔离断言失败。
