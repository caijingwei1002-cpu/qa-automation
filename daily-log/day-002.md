## 学习记录

今天理解了：checkbox 测试应使用 `check()` 表达“确保最终选中”的目标状态，并从控件状态、Todo 状态和业务结果三个层面验证完整状态转换。

它解决的问题：避免只断言 checkbox 被选中而产生假通过；即使控件状态改变，也必须证明 Todo 获得 `completed` 状态且未完成计数同步更新。

我实际如何使用它：新增 `test_complete_todo`，先创建一个 Todo 并确认未完成数为 1，再调用 `toggle.check()`，最后断言 checkbox 已选中、Todo 行类名为 `completed`、未完成数为 0。

遇到的问题：首次验证在 fixture 打开 `http://127.0.0.1:8080/` 时连接被拒绝，测试没有执行到 checkbox 交互；通过 PyCharm 调试器启动时还出现了 debugpy 环境提示。

根因或当前假设：TodoMVC 的本地 HTTP 服务未运行，属于被测环境不可用而非测试代码错误。启动 `D:\qa-automation-targets\todomvc\examples\angular\dist\browser` 的 HTTP 服务后，目标测试通过。
