## 学习记录

今天理解了：源码依赖图回答设计上应该连接谁，live survey 回答当前实际上命中了谁；只有身份成立后，HTTP 响应才有资格进入产品契约判断。

它解决的问题：避免把 UI 页面成功、BFF 包装错误或错误服务的状态码误报为目标后端缺陷，也避免把环境 override 和默认基线混为一谈。

我实际如何使用它：从 `next.config.js`、BFF route 和组件调用点建立静态地图，再对端口/PID/GET 保存真实 live 分类，并明确不启动 UI 或进入 E2E。

遇到的问题：Room 默认 `3001` 仍由外部 Express 占用，Booking、Auth 和 UI 当前没有监听；因此依赖地图完成，但平台业务链没有建立。

根因或当前结论：3000/3003/3004 为 `SERVICE_UNREACHABLE`，3001 为 `SERVICE_IDENTITY_MISMATCH`。这是依赖/运行状态结论，不是 UI、API 或 Room 产品缺陷结论。
