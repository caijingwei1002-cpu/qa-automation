## 学习记录

今天理解了：BFF route + Mock HTTP client 可以在不启动真实服务的前提下验证代理层如何处理下游 HTTP error、连接异常和超时，但不能替代真实服务身份和契约验证。

它解决的问题：避免把 500 + [] 当作下游 500，避免把 mapper 单测误当作 route 边界通过，也避免为了诊断而泄漏 token、Cookie、敏感 body 或内部拓扑。

我实际如何使用它：设计 M1 ConnectionError、M2 下游 404、M3 下游 500、M4 Timeout；分别记录 bff_status、downstream_status、exception_category，并对 response 和日志两个出口设计脱敏断言。

遇到的问题：统一错误映射可能把 ConnectionError、Timeout、下游 404/500 压缩为同一个 500 + []，如果日志只有 request failed，就无法恢复故障类别。

根因或当前结论：这是 BFF 可观测性和错误映射边界问题，不是已访问真实 Room 后形成的 Room 产品缺陷结论。
