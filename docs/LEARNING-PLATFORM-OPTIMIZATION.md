# 学习平台优化实施说明

实施日期：2026-09-18

本轮只优化课程、教学记录、验收、验证安全、证据和仓库规范，不修改工作台代码，不启动或停止外部服务，不推进学习进度。

## 已实施顺序

1. **安全验证入口**：课程声明 `none`、`observe` 或 `start` 服务策略。默认只读；`start` 必须显式选择。已有监听只有匹配登记的只读身份特征才可继续，通用 200、无输出或权限不足均不能自动形成服务身份结论。
2. **课型与能力合同**：课程声明 analysis、coding、debugging 或 assessment，并关联能力目标、产物类型、验证层、是否要求可执行实现和禁止结论。
3. **贡献与掌握证据**：Day 77 起分别记录学习者贡献、教练贡献、产物类型、验证范围和 mastery level。历史记录保持原样。
4. **完成校验**：编码课必须有代码或测试证据，pytest 结果必须包含执行汇总，`git diff --check` 不能替代目标测试，要求独立实现的课程必须通过无提示迁移。
5. **结论分层**：运行证据分别记录自动化执行、验证层、真实环境和产品契约，不再使用一个 PASS 覆盖所有层级。
6. **课程与知识维护**：新增 Day 77 隔离编码课；新知识从 Day 77 起按日拆分，Day 1–76 的历史知识保留在原文件。
7. **格式与生成一致性**：加入 EditorConfig、Git attributes、生成 Markdown 一致性校验、课程细化范围校验和维护范围 Ruff 门禁。
8. **历史证据治理**：用独立审查文件说明 Day 67–76 已证明和未证明的能力，不撤销历史完成状态，也不补造证据。

## Day 77 试运行合同

Day 77 是 coding 课，目标是在测试资产中独立实现服务身份判定纯函数和参数化测试。服务策略为 `none`，只运行隔离测试，不访问真实 Room，不启动、停止或替换外部服务。完成时必须证明测试被收集和执行，并完成一个无提示的新证据组合迁移；单元测试通过不能写成真实 Room 身份或契约通过。

## 仍需通过真实学习验证的事项

工具测试只能证明规则能执行，不能证明教学体验已经理想。Day 77 实际学习时需要观察：记录字段是否过重、学习者是否能在不过度提示下完成实现、审查修改是否形成闭环，以及结论分层是否容易理解。根据这次真实试运行再调整字段，不以工程测试代替学习验收。
