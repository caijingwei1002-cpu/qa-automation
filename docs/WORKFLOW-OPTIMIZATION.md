# 每日学习规范优化交付记录

本轮优先解决每天入口、顺序、证据和完成判定不一致的问题。从 Day 67 起启用七步记录，当前学习进度保持不变。

## 已按顺序完成

1. **统一教学流程**：`config/learning-workflow.json` 定义七步，生成计划、工作台导航、日志模板和教练规则使用同一套顺序；`docs/INTERACTIVE-LEARNING.md` 解释学习者与教练的职责。
2. **持久化续学状态**：`plan_day.py session/checkpoint` 保存实际进展、卡点、帮助程度和证据。读取计划不会开课；点击导航不会完成步骤；修订前序步骤后，后续验收需要重新进行。
3. **完成校验**：检查七步、独立迁移、用户确认、知识章节、目录索引、日志和验证结果。失败不推进，重复完成不重复写历史，不能跳过当前日。
4. **统一验证入口**：CLI、MCP、工作台共用执行模块，记录目标测试和回归的命令、退出码、输出、时间、来源和代码指纹，每次运行有独立快照。学习者提供结果走明确的导入入口。修改代码或重跑后需重新验收。
5. **修正项目映射和历史归属**：区分课程所属阶段与实际执行项目，Day 66 的 UI 课程对应 UI 回归和服务。更正 Day 66 日志中没有依据的独立完成描述，保留已完成历史，不补造迁移回答。
6. **加入自动检查**：CI 增加工具和工作台测试；工作台测试使用本地模拟服务，不需要登录账号。

## 使用体验

学习者仍然说“开始 Day N”“继续”“我改好了，请检查”“完成 Day N”。教练负责读取状态、逐步指导、记录证据和执行收尾，不增加学习者填写 JSON 的负担。

首次开课先核对进度并复习；中断后回到第一个未完成步骤。固定的是顺序、职责和验收标准，问题内容和帮助程度根据实际学习调整。
