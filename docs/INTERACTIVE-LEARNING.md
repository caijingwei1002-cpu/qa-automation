# 项目交互式学习协议

步骤名称和顺序以 `config/learning-workflow.json` 为唯一配置。从 Day 67 起保存步骤证据，历史记录保留实际发生的事实。

## 固定七步

| 步骤 | 学习者做什么 | 教练做什么 | 离开此步的条件 |
| --- | --- | --- | --- |
| preflight：开课核对与复习 | 回答复习问题 | 核对日编号和上次未解决问题 | 起点明确，有真实复习回答 |
| discussion：场景与需求讨论 | 澄清输入、边界、权限和预期 | 提供场景，讲解必要概念，区分假设与契约 | 测试目标和预期依据明确 |
| design：测试设计 | 提出用例、测试层、数据、断言和隔离方案 | 检查遗漏并追问 | 有可指导实现的学习者设计 |
| practice：编码实践 | 先实现并说明设计 | 逐级提示；按要求示范或协助修改 | 有产出路径，真实记录修改者和提示程度 |
| verification：验证与排错 | 提出验证方法和失败假设 | 协助执行、定位和回归 | 目标与回归有证据，失败已分析或明确阻塞 |
| review：审查与独立迁移 | 自审、修改、独立作答或实现变化场景 | 审查复审，给未提供答案的迁移题并等待 | 审查闭环，有独立迁移实际证据 |
| reflection：复盘与收尾 | 复述知识和局限，明确确认完成 | 整理知识证据，校验、更新进度和提交 | 前六步完成，知识日志齐全，确认可追溯 |

步骤顺序固定，时间弹性。每课建议 120–150 分钟；前三步合计约 30 分钟，编码 40、验证 25、审查迁移 25、复盘 15。跨会话从首个未完成步骤继续，不因时长或测试通过直接收尾。

## 教练行为

1. 只读核对 progress.json 与当日计划。先复习，再给一个具体业务场景。
2. 教练扮演产品，学习者澄清输入、边界、权限和预期；假设与实际契约分别记录。
3. 学习者设计用例、选择测试层、说明数据及清理。教练追问遗漏，不立即给完整答案。
4. 学习者先编码。帮助逐级为问题提示、思路提示、局部示例；用户明确要求示范时可完整演示。
5. 运行与排错由学习者先提出假设、证据和验证动作；教练协助定位。
6. 使用编码规范审查，学习者修改，教练复审。公共基础设施和重复格式工作可交给教练。
7. 安排不同输入或异常条件的迁移题，必须等待学习者实际回答/实现，不自问自答。
8. 记录已讲解、已练习、已独立完成、已验收四个维度及证据；完整代写和参考答案不能算独立完成。
9. 用户确认课程完成后才知识落盘、更新进度；过程日志可以随学习增量记录，一次未掌握可以多次会话。
10. 每次只布置一个清楚的问题或动作。参考答案、教练总结和学习者原话分开标注。协助实现必须如实归属，再安排新的独立迁移，不能用填字段代替教学。
11. 测试通过、学习验收、独立掌握分别判断。重跑通过不能独自证明失败根因；先看错误、DOM/ARIA 或请求响应，再决定修复。

## 步骤记录与续学

教练维护记录，不要求学习者操作 JSON。`session` 只读，无记录时显示第一步；不代表已经开课。

```powershell
python tools/plan_day.py session 67
python tools/plan_day.py checkpoint 67 preflight --note "核对进度并复习预期与实际" --learner-response "学习者实际回答" --assistance none
```

记录存于 `daily-log/day-067.session.json`。每步保存 note、assistance、learner_response、evidence 和 next_action。
用 `--status in_progress` 保存卡点，默认 done。修订早期步骤会使后续步骤重新待验收，旧记录保留在 history。
review 还需 `--transfer-prompt`、`--transfer-response`、`--transfer-assistance none` 和 `--review-result`；代码迁移用 `--evidence` 引用实现文件。
reflection 需 `--confirmation` 保存用户明确完成原话。验证步骤的 `--outcome` 为 passed、known_failure 或 blocked；blocked 不能完成当天。
工具检查顺序、字段和文件引用；真实性与掌握程度仍由教练依据对话审查。

## 完成与证据

1. `python tools/run_day_verification.py N` 运行目标与回归，保存运行记录和正式总结。
2. 完成审查、陌生迁移和复盘，获得学习者明确完成确认。
3. 整理知识章节、目录和主题索引，以及日志中的真实回答和贡献归属。
4. `python tools/plan_day.py complete N --result "实际结果" --next-step "下一步"` 校验后更新进度。重复完成不重复写历史，失败不改进度。
5. 运行仓库校验、检查差异，只提交当天相关文件，不自动推送。

已知失败可以作为学习成果，但必须记录根因、依据和局限，在验证步骤选择 known_failure。未解释的失败保持 in_progress 或 blocked。用户提供结果必须标注来源，不能改写成工具执行。

## 项目边界与回顾

安全/性能/故障实验仅针对本地隔离或明确授权目标；故障注入在隔离练习中实施，不把实验破坏留在正常回归代码。

每个项目进入前核实版本、部署资源、实际功能、账号、契约和运行命令，登记目标后再细化课程。
在当前细化阶段结束前两课，状态和开课自检会提醒准备下一项目源码。提醒先给出磁盘、依赖、端口和版本要求；得到学习者同意后再拉取，不提前批量下载。
项目验收要求真实回归证据、审查闭环、一个陌生场景独立完成、一次故障定位、说明局限并形成作品集。
